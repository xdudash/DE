# ADR-0012: Installable PWA shell and a narrow offline promise

- Status: Accepted (implemented in DG-016)
- Date: 2026-10-20
- Decision owner: Project owner (delegated to the delivery agent under the owner's instruction of 2026-10-19; reversible)

## Context
[ADR-0001](./ADR-0001-application-platform.md) chose a mobile-first web app with a PWA manifest, with Capacitor store apps later (P8). Until now the manifest named the app and nothing else: no icons, so no browser offered installation, and the app had no phone navigation of its own. Learners in Germany, Austria and Switzerland use this mostly on a phone, often on patchy mobile data in a waiting room at an office.

Two things were missing and they are different problems:
1. **Installability.** A browser offers "add to home screen" only when the manifest has a name, a start URL inside the scope, a standalone display mode, 192px and 512px icons, and the page has a service worker with a fetch handler.
2. **Offline tolerance.** [ROADMAP](../../development/ROADMAP.md) puts the attempt queue and sync in P3. That is about *uploading* evidence. Being able to *read* a lesson already opened is a separate, smaller promise that needs no server.

## Options considered
| | A. Manifest + minimal worker (chosen) | B. Manifest only | C. Full offline app (precache all lessons) |
|---|---|---|---|
| Browser offers installation | Yes | No (no fetch handler) | Yes |
| Reading an opened lesson offline | Yes | No | Yes |
| Risk of serving stale lessons | Low (network first) | None | High without a sync story |
| Size downloaded up front | Page the learner opens | — | Whole bundle, all languages |
| Work now | Small | None | Large, and needs P3 sync first |

Option B does not meet the goal: the app cannot be installed. Option C pre-empts P3: caching every lesson implies a content-version and invalidation story that belongs with sync, and it would download content in languages the learner never opens.

## Decision
- **Installable:** the manifest (`apps/web/lib/pwa/manifest.ts`, served by `app/manifest.ts`) declares id, scope, standalone display, 192px and 512px icons and a 512px maskable icon. Icons are generated by `apps/web/scripts/make-icons.mjs` and committed, so every binary in the repository has a reproducible origin.
- **Service worker** (`apps/web/public/sw.js`), registered in production only:
  - navigations are **network first**, falling back to the cached page and then to `/offline`;
  - build assets and icons are cache first, because their URLs change with the build;
  - `/api/*` and every non-GET request bypass the cache entirely, so an attempt is never answered from a cache.
- **The promise we make** is exactly: *pages you have already opened stay readable without a connection*. The install hint says that and nothing more. Answers given offline are not uploaded, and the app does not claim they are; offline attempt sync stays in P3.
- **Phone navigation:** sections live in a bottom bar within thumb reach below 48rem, and in the header above it; the two never show at once. Safe-area insets keep content clear of notches and the home indicator.
- Registration is skipped in development, where a cached shell would hide code changes.

## Consequences
- Updating the worker means bumping `VERSION` in `sw.js`; old caches are deleted on activate.
- `skipWaiting` plus `clients.claim()` means a new worker takes over without waiting for every tab to close. Acceptable here because pages are read-only content; it would need revisiting once attempts are queued locally.
- The first visit is not controlled by the worker, so a page is cached from the second load on. This is why the E2E test loads a lesson twice before going offline.
- iOS does not fire `beforeinstallprompt`, so Safari shows no install button; the app still works and can be added from the share sheet. We do not show instructions for a button that does not exist.
- A phone bottom bar costs vertical space; `.page` reserves room so the last item is never hidden behind it (covered by an E2E test).
